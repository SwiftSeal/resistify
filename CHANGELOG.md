## [v2.0.0](https://github.com/SwiftSeal/resistify/releases/tag/v2.0.0) - 2026-03-05

Exciting times! Resistify is now really really fast.

### New features

* The previous NLRexpress `jackhmmer` backend has been completely replaced by a new classifier that uses ESM2 8M embeddings. It is substantially faster and in most cases more accurate. It can be accelerated via GPU and MPS, but CPU inference is also very fast. Motif predictions will change as a result of this new model. As part of this, the TIR motifs have temporarily been removed. This is not expected to change classifications.
* The plotting method has been changed - plots are now generated as SVGs (one per sequence), and are generated by default in the results directory. Plots can be hidden with `--no-draw`.
* More HMMs have been added to the default NLR database, including Pfam-A LRR models. This should improve domain annotation accuracy slightly, but otherwise should not affect classification accuracy.
* HMMER dependency has been replaced by `pyhmmer` - it should be slightly faster and more stable.
* There has been a lot of refactoring - refer to the README.md for up-to-date result formats.

### Bug fixes

* Probably added a few with this update - raise an issue if you find any...

## [v1.3.0](https://github.com/SwiftSeal/resistify/releases/tag/v1.3.0) - 2025-06-27

### New features
* Newer releases of `pytorch` were incompatible with the method used when model data was downloaded manually. `download_models` has been revised to *exclusively* use `$HF_HOME` and `$TORCH_HOME`, or the default model storage locations if these variables are not set. The `--models` argument has been removed - instead, users should use `$HF_HOME` and `$TORCH_HOME` if they wish to specify an alternative cache location.
* Some quality of life improvements.

### Bug fixes
* Turns out `download_models` was accidentally downloading a set of model data that was never used! Total download size is now 10G smaller...

## [v1.2.1](https://github.com/SwiftSeal/resistify/releases/tag/v1.2.1) - 2025-06-16

### New feature

### Bux fixes

* Similar and adjacent domains now correctly merge in `prr`, and reported correctly in `domains.tsv` - previously, the majority of annotations were only present in `annotations.tsv`.

Also made various changes which should improve performance slightly.

## [v0.7.0](https://github.com/SwiftSeal/resistify/releases/tag/v0.7.0) - 2024-12-16

* HMMER searches now use recommended per-profile thresholds rather than a generic cutoff. Expect minor changes in NLR classification for partial or highly degraded NLRs, and the PRR classification will be much more stringent! As a result of this change, the E-value argument has been dropped.
* Long processes now have dynamic progress bars, and output static % progress logs.
* More verbose warning if running PRR pipeline CPU-only mode.
* Will now dynamically assign chunksize if not set manually for improved performance.
* Extracellular length of PRRs is now reported. 
* Can now take gzipped fasta files as input
* If no NLRs/PRRs are detected, Resistify will no longer produce an error code 1. It will instead exit without error and produce empty output files.
* Removed bioconda as a dependency - should reduce dependency resolving time slightly and improve image size
* Fixed a significant bug where nlrexpress multiprocessing could silently freeze for "reasons". As a result of this change, debug logging for all nlrexpress subprocesses is disabled.

## [v0.6.0](https://github.com/SwiftSeal/resistify/releases/tag/v0.6.0) - 2024-11-22

### What's new in v0.6.0?

The release of `v0.6.0` has brought a number of changes to `Resistify`.
First, you'll note that there are now two modes available - NLR and PRR - which identify NLRs and PRRs respectively.

The NLR pipeline is largely the same, but has received multiple performance improvements which should allow it to utilise more threads simultaneously and significantly reduce memory usage.
As a result of these changes, the `--threads` mode has now been removed which was a bit of a lie anyway, as numpy would use them all regardless.
The `--ultra` setting has been renamed as `--retain`.

The PRR pipeline is new to `Resistify` and is currently in development.
It uses a re-implementation of [TMbed](https://github.com/BernhoferM/TMbed) to predict transmembrane domains, from which it will identify and classify RLP/RLKs according to a [recently described classification system](https://doi.org/10.1016/j.molp.2024.02.014).
Feel free to give it a try and offer suggestions!
Due to other commitments I can't currently benchmark this properly and make no guarantees to its accuracy yet.
